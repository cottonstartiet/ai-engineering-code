Under the hood: details worth knowing

The displayed graph is a business map, not a literal executor inventory

The UI shows 12 business nodes. In the returns backend, identify is an event emitted by intake, not a separate executor. Approval persistence is a service call; approval, execute and verify run in a second workflow. Confirmation is an application event. The interactive returns map above reflects actual investigation executors.

The coordinator is not the final structured assessment writer

Delivery captures intermediate specialist text, concatenated by author rather than retained as a chronological turn list. A separate ResolutionWriter receives that discussion plus request, order and policies. The final agent_message labeled IncidentCoordinator contains the writer's assessment summary; the coordinator's final text is not directly used as the persisted business assessment.

Specialists share tools; prompts establish their roles

All three specialists receive order_facts, tracking_facts and policy_evidence. Tool activity actor labels are hardcoded inside those tool functions, so the activity label alone does not establish which specialist called a shared tool. The coordinator is instructed to involve everyone, but this is not enforced by an application-side participation condition.

Model configuration and finite budgets

model_client() creates an AsyncOpenAI-backed OpenAIChatClient shared by agents within the investigation. Agents set store=false and use framework-managed local conversation history. Defaults are 12 participant turns, 2 transient provider retries, 120 seconds active work, a renewable 180-second job lease, and 2 worker slots. A model call or agent run may involve multiple provider requests; one proposal invocation is not a promise of one HTTP call.

Clarification, failure and cancellation are explicit lifecycle operations

Customer information and retry create linked runs using stored inputs, not a restored agent conversation. Expired investigation jobs are interrupted; eligible unfinished execution jobs can be requeued. Cancellation stops pending work but cannot undo a committed simulated resolution. Human waiting occurs between jobs and does not hold an active investigation timeout open.

The assessment contract is deliberately small
{
  outcome: "propose" | "clarify" | "escalate" | "inform",
  summary: string,
  question: string,
  action: "refund" | "replacement",
  citations: string[]
}

complete_assessment() rejects unavailable citations. A proposal additionally requires nonempty citations including its authorization policy, current eligibility, and later human approval. Money and quantities do not come from model-generated assessment fields.
